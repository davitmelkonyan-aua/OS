Assignment 2:

The padding in the struct are applied as follows. Since char taeks 1 byte, int takes 4 bytes and double takes 8 bytes,
in the first struct char comes first taking 1 byte, however 3 bytes of padding are added next for the coming int to be
alligned at an address divisible by 4 (the byte size of int), and next comes the double which takes 8 bytes and will be alligned.
This means the struct takes overall 16 bytes, with the padding added, ensuring our fields are alligned and if we make an array of 
structs we shall have everything alligned.

When changing the order of fields in the second struct, the output shows 16 byte size for the struct again, meaning the order
did not change the size. This is because, we have a double of 8 bytes, next an int of 4 bytes which are alligned, and a char of 1 byte taking
13 bytes in total. However 3 bytes of padding are added in order to make sure that if another similar struct was added at the
next pointer it would be alligned as well, and if we had an array of structs all of them and their fields would be alligned.

Without the #pragma pack() directive we are getting a usual setup like in assigment 2. But when adding #pragma pcak() we
can specify the maximal allignment up to certain amount of bytes. In the first example it is 1, which means that the distance
